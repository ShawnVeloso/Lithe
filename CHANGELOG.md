- **Fix: 5 of 9 tools were unreachable on Gemini.** The tool closures were named `profile_data_wrapper`, `inline_chart_wrapper` and the three `*_watch_rule*_wrapper` variants to avoid shadowing their module-level imports. The google-genai SDK builds each `FunctionDeclaration` from `callable.__name__`, so the model was told the tools were called `profile_data_wrapper` — while `tool_map` was keyed `profile_data`. Dispatch missed and the model received "Tool profile_data_wrapper not recognized", so dataset profiling, charting and all watch-rule management silently failed on the primary provider (Ollama was unaffected: its hand-written schema used the correct names). Fixed by aliasing the imports (`profile_data as _profile_data`) so the closures can take the public names, and deriving the dispatch map as `{fn.__name__: fn for fn in tools}` — a hand-maintained second list of names is what let declaration and dispatch drift, so the class of bug is now structurally impossible. Applied to both `chat()` and `chat_stream()`. Side effect: the `call.name == "inline_chart"` branch stops being dead code, so charts reach the UI. Also dropped two `print()` calls from the renamed `search_files`. 7 xfail tests flipped to passing; suite 56 → 63 passing. Branch: `fix/gemini-tool-name-mismatch`.
- **Fix: stop defects masquerading as connection failures.** Both `chat()` and `chat_stream()` caught `(errors.APIError, httpx.TimeoutException, Exception)` — where the bare `Exception` subsumed the tuple and wrapped the entire post-call body. A `KeyError` from a model omitting a tool argument, a `UnicodeDecodeError` in the diff builder, or an `IndexError` on a safety-blocked response were all logged as "Gemini connection failed" and silently rerouted to Ollama, so real bugs were indistinguishable from outages and quietly changed engines mid-conversation. Split into a transport branch (`APIError`, `TimeoutException`, `TransportError`) that still falls back, and an explicit defect branch that logs a traceback via `logger.exception` and returns an internal-error message without switching engines. Replaced the four `print()` calls in those handlers with structured logging. In scope for this pass because it also corrupts the capability evaluation: a masked bug would otherwise be scored as the model giving a bad answer. Suite 63 → 64 passing. Branch: `fix/narrow-exception-handling`.
